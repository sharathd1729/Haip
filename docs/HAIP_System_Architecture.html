Key Data Flows

📞 Inbound Call → Wrap-up Card

1

Guest calls IVR (CallerDesk/Acefone) → IVR greets, captures consent, forwards to agent's mobile

2

Call ends → IVR sends webhook to /webhooks/callerdesk or /webhooks/acefone

3

Celery: call_ingest → downloads recording → stores to S3 (KMS encrypted)

4

Celery: transcribe → Sarvam AI → transcript stored to DB

5

Celery: judge + wrap_up → Claude Sonnet → QA score, disposition, missed revenue flags

6

Redis pub/sub emit → SSE endpoint → wrap-up card appears in cockpit within ~90 sec

7

Automation: fire_trigger(call_completed) → engine checks active rules → fires actions

💬 WhatsApp → AI Concierge → Reply

1

Guest sends WhatsApp message → Meta delivers webhook to /webhooks/whatsapp

2

Webhook validates signature, dedupes by WAMID, creates Message row, triggers identity resolution via identity_service.resolve_gid()

3

Celery: concierge_draft → Claude Haiku → reply drafted from property knowledge base

4

Draft appears in Unified Inbox for agent review (Shadow Mode). Agent taps Approve or edits.

5

Celery: send_whatsapp → Meta Cloud API → message delivered to guest

6

Celery: generate_ai_summary debounced 30-min → updates inquiries.ai_summary in DB

📣 WhatsApp Campaign Broadcast

1

Agent creates campaign in UI: selects template, audience (tags + source), schedule

2

POST /messaging/campaigns/{id}/launch → enqueues run_campaign Celery task

3

Worker resolves template, pulls WA integration creds, builds recipient list from subscriber table

4

Sends in batches of 50 with 1s inter-batch delay (Meta rate limit compliance)

5

Live counters (sent/failed) updated per batch. Final status: COMPLETED / FAILED.

⚡ Automation Rule Fire

1

Trigger event: new_inquiry (from endpoint), call_completed (from wrap_up task), or timer event (from check_automation_timers Beat task)

2

fire_trigger.apply_async() — always async, always in try/except, never blocks the response

3

Engine fetches active rules matching event + tenant · Evaluates trigger_config conditions

4

Dispatches action: send_wa_template / create_draft / notify_team / move_followup / tag_guest

5

Records AutomationRun (success/failed/skipped) · Updates rule.run_count and last_run_at

🧠 Guest Identity Resolution

1

Inbound signal arrives: phone number from IVR, WA account from webhook, Instagram PSID, email

2

identity_service.resolve_gid(signal_type, signal_value, tenant_id) — only place this can happen

3

Queries guest_identities table · Calculates composite confidence across all matching signals

4

If confidence ≥ 0.85 → returns existing GID. If < 0.85 → creates new guest + GID.

5

Writes DPDP consent row if signal type is phone or email (consent_source = "agent_manual")

🔒 Multi-tenancy Enforcement

1

Every API request → get_current_user() validates JWT → extracts tenant_id

2

set_tenant_context(db, tenant_id) → sets PostgreSQL session variable for RLS

3

RLS policy on every tenant-scoped table: tenant_id = current_setting('app.tenant_id')

4

Celery workers also call set_tenant_context() before any DB access

5

Webhook shared secrets are per-tenant — no global secrets. KMS keys are per-tenant.
