1.  What's Changed
Four decisions reset the plan since the v2 PRD. All four shrink scope, sharpen positioning and pull cost down. None of them invalidate the underlying architecture — the adapter pattern carries forward and the hospitality data model is unchanged.
#
Change
What it means in practice
1
No in-app calling
Agents answer calls on their personal mobile (the IVR forwards). HAIP is post-call intelligence + pre-call prep + click-to-call trigger — never the active call surface.
2
CallerDesk or Acefone
These two are the India-SMB-priced IVR providers we integrate with. We drop Exotel/Plivo as the default — keep them as future adapters.
3
Ratha is the design partner
A luxury caravan / experiential-journey operator. Low call volume, high deal value, multi-day pre-trip engagement. Build HAIP for them first; generalise to all hospitality SMBs in V2.
4
Strict cost ceiling
Every third-party tool we put on Ratha's stack has to fit inside ₹20,000 / month total HAIP infra cost. For new clients (Jade, etc.) the published plan must come in under ₹10,000 / month — and we still need a margin.
CONSEQUENCE — What this unlocks
Way faster client onboarding — no live-call infrastructure to ship, no real-time streaming complexity, no SIP fork to debug.
Lower infra cost — no live SIP processing, no GPU-hot live transcription, no WebSocket transcript stream. We process recordings asynchronously, which is much cheaper.
Cheaper client price-point — fits the ₹10K plan ceiling without margin collapse.
BYOC stays the model — clients keep their own CallerDesk/Acefone account and pay them directly for telephony. HAIP is pure SaaS overlay.
2.  The New Agent Flow
The agent cockpit changes from a "live call panel with dialler, mute, hold and live transcript" to a "before-and-after-the-call workspace". Same data model, same value props (Auto-QA, coaching, scorecards) — but the cockpit is no longer a real-time telephony surface.
2.1  Inbound call flow
Guest dials the property's virtual number (provisioned on CallerDesk/Acefone in the client's name).
IVR plays the greeting + recording-consent prompt. Optional language menu.
IVR forwards the call to the on-duty concierge's personal mobile (via simultaneous-ring, sticky-routing, or round-robin per the client's setup).
Concierge picks up on their phone and has the conversation. They have no HAIP screen open during the call — it's a normal phone call.
Call ends. CallerDesk/Acefone POSTs a webhook to HAIP with the recording URL, duration, caller number and agent leg ID.
HAIP processes asynchronously: dedup Guest by phone → upsert · create Call record · link to existing Inquiry or create new · fetch recording from IVR CDN · store on S3 · transcribe · run AI judge · write score with evidence spans.
Within 90 seconds of call end, the concierge's cockpit shows a post-call wrap-up card: AI-drafted summary · disposition picker (Hot / Quoted / Booked / Lost / Callback) · suggested next action.
Score and theme propagate to the Reservations Pulse, Owner Daily, and Compliance Center surfaces.
2.2  Outbound call flow (click-to-call)
Concierge opens a Guest record or an Inquiry in HAIP. Sees the prep card: lifetime stays, past objections, AI-suggested opener.
Clicks the green "Call" button. HAIP calls the IVR provider's click-to-call API: "ring agent's mobile, then bridge to guest's mobile".
Agent's personal phone rings. Agent picks up, hears a brief beep, then the guest's phone starts ringing.
Guest picks up. Conversation happens entirely between the two mobile phones. The IVR records it in the background. No HAIP screen during the call.
Call ends. Same async processing as the inbound flow.
After-call wrap-up appears in cockpit. Concierge picks disposition, edits the AI summary if needed, schedules a follow-up if needed.
2.3  What the cockpit surfaces today (post-pivot)
Today's queue — inbound waiting (rare; mostly forwarded directly), callbacks scheduled, follow-ups due, outbound dial list.
Prep card on the Guest 360 — last 5 conversations, lifetime value, predicted CSAT, suggested opener.
Click-to-call button — one click triggers the IVR bridge.
After-call wrap-up — AI summary, disposition picker, suggested next action, schedule follow-up.
Personal scorecard — today's calls, conversions, talk time, QA score, 7-day trend.
Coaching nudge — one fix to apply this week from the team lead.
Knowledge cards — quick RAG lookups for "what's our pet policy", "rate card for June", etc.
PROTOTYPE — Cockpit work to redo in the existing prototype
Remove the live-call card (timer · mute · hold · transfer · hangup · live transcript stream).
Replace with a "current call · ringing your mobile" notice when an inbound call lands, and a click-to-call trigger for outbound.
Add the after-call wrap-up panel that appears after the IVR webhook fires.
Keep the queue, scorecard, AI assist (now becomes pre-call prep + post-call summary, not in-call whisper).

5.2  Why these choices
FastAPI + Postgres + Celery is the cheapest "real backend" stack for India in 2026. Single VPS or small EC2 can run all three at low volumes. The same code scales to enterprise.
pgvector instead of Pinecone/Weaviate. One database vendor. Zero per-vector cost. Easily handles a few million vectors per tenant before we need to think about it.
Next.js + Vercel free tier in Phase 1. Costs nothing until ~100K page views/month. By then we're at scale and can afford the upgrade.
Cloudflare free everywhere. DNS · CDN · WAF · SSL · DDoS protection · analytics — all free, all production-grade.
Open-source observability (Sentry + Grafana free tiers). Self-host Plausible for analytics if even ₹500/mo matters.
Claude API as the LLM. Haiku is cheap enough to use for everything at low volume. Sonnet upgrade only for ambiguous edge cases. No GPU bill until we choose to add one for Whisper.
6.  Security & Multi-tenancy
Security is non-negotiable even at Phase-1 scale, especially because we're storing voice recordings and PII for paying clients. Multi-tenancy must be airtight from day one — a tenant accidentally seeing another tenant's data is an existential bug.
6.1  Multi-tenant data isolation
Every row in every table carries `tenant_id`. Compound primary keys where appropriate.
Postgres Row-Level Security (RLS) enforced at the DB layer. The app server sets `current_setting('app.tenant_id')` on every request; RLS policies filter every query.
No application code is trusted to filter by tenant — RLS is the safety net.
Per-tenant KMS data keys for recording encryption. Tenant A's key cannot decrypt Tenant B's recordings, even if their data leaks.
Test: end-of-week regression test that simulates "admin of tenant A logs in, tries to fetch Tenant B record by guessing IDs" — must return 0 rows / 403.
6.2  Encryption
At rest: AES-256 on S3, on RDS (storage encryption + per-column encryption for PII fields).
In transit: TLS 1.3 everywhere, including app↔DB and worker↔S3.
Secrets: AWS Secrets Manager. No secrets in env files, no secrets in code.
BYOK on Enterprise tier (V2) — customer brings their own KMS key.
6.3  Access control
Roles: Owner / Manager / Reservations / Concierge / FOH / Marketing / Compliance / Read-only.
Plus attribute-based: villa-scope (concierge for Villa A only sees Villa A).
SSO via Google + Microsoft on the free tier (NextAuth). SAML / SCIM on Enterprise (WorkOS).
Audit log append-only, hash-chained, 5-year retention. Every score, override, export, login, role change.
Session: 15-min access JWT + 30-day refresh; revoke on password change.
MFA mandatory for Owner + Compliance roles.
6.4  PII & DPDP
PII redaction at L1 — before transcripts reach the LLM. Card / Aadhaar / PAN / phone / email → reversible tokens.
Per-tenant data residency. India tenants live in ap-south-1. EU guest data isolated to eu-central-1 on Enterprise.
Delete-on-request flow — guest record + linked rows + recordings purged within 30 days; audit entry recorded.
Sub-processor list public on the HAIP trust centre. DPAs signed with Anthropic, Deepgram, AWS, CallerDesk/Acefone.
Recording consent prompt in the IVR flow. Consent event logged in HAIP's consent log.
Annual third-party penetration test from Year 2.
6.5  BYOC credentials security
IVR account credentials (CallerDesk/Acefone API keys) encrypted with per-tenant KMS keys.
Decrypted only by the worker process when calling the IVR API. Never logged, never echoed.
Credential read events go to the audit log.
Credential rotation supported with zero downtime.
Tenant can revoke HAIP's API access from their IVR provider at any time — we detect within 5 minutes and pause processing.

7.1  When we move between phases
Phase 1 → 2 trigger: p95 API latency > 600ms OR CPU > 70% sustained OR DB connections > 70% pool.
Phase 2 → 3 trigger: monthly bill exceeds ₹40K OR > 15 paying clients OR any single tenant exceeds 30K calls/month.
Phase 3 → 4 trigger: EU customer signs up OR a single tenant requests dedicated VPC OR DB exceeds 1 TB.
7.2  What does NOT change between phases
The application code. Same FastAPI, same Next.js, same Postgres schema.
The data model. Same Guest, Inquiry, Conversation, Call, Stay, Score.
The customer experience. Tenants on Phase 1 and Phase 3 see identical UIs.
The pricing. Tier prices stay fixed; only the underlying infrastructure changes.
